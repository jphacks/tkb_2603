## 製品概要
### 背景(製品開発のきっかけ、課題等）
AI でコードを書くのは速くなりました。でも人の仕事は消えず、AI が出したものを**読んで、確かめて、判断する**側に移りました。速くなった分、こなす量も増えています。
- 2026 年の調査では、開発者の 75% が「検証の責任が増えた」と答え(Atlassian State of Developer Experience 2026)、85% が「詰まる場所がレビューと検証に移った」と答えています(GitLab 2026)。どちらも自己申告の業界調査です
- AI を使うと 1 回の課題の負荷は下がります。それでも、確認の負荷が高いほど疲れが強くなっていた、という研究があります(Fan et al., CHI 2026)

私たち自身も、AI を並列で動かして開発するうちに、確認と判断が詰まって頭がぐったりする経験をしてきました。それなのに、休むタイミングは多くが時計か気合で決まっています。

### 製品説明（具体的な製品の説明）
ChatGPT Web の上で動く Chrome 拡張です。AI とのやりとりの中身から「脳にかかる負担の目安」を器のようにためていきます。器がいっぱいになったら、**作業の途中ではなく区切りのいい瞬間に**「○分休もう」と声をかけます。

1. ChatGPT でのやりとりから、**読む量・判断を求められた回数・確認や検証(エラーとの格闘)・話題の切替・作業時間**の 5 つを取ります
2. 5 つの平均で、器に負担がたまります。中身が重いと速く、軽いと遅くたまります
3. 器が 80% を超えたら、生成中でも入力中でもない区切りを待って、休憩を提案します。どの要素がためたかの内訳(例: 「確認・検証 38% / 読む量 27% / 作業時間 20%」)と、それに合わせた声かけ(例: 「🐛 エラーと戦い続けてる! 確認続きでおつかれさま💪」)を出します
4. 休憩中は円のタイマーとストレッチのピクトグラムを出します。休む前には「戻ったら何をする?」を 1 行メモできます
5. 戻ったら、メモと励ましの声かけを出します。最後に「この休憩どうだった?」と聞きます

- 判断と確認の一部は、Anthropic の API キーを使って会話を分類して取ります。キーが無くても、エラーの貼り付けや会話の切替などの手がかりで動きます(判断は「未計測」になります)
- **なぜ ChatGPT Web から?** 一番多くの人が使う入口なので、まずここで確かめました。計算の部分は画面と切り離してあり、Claude Code の hooks を使えば承認待ちやテストの失敗まで取れます(今後の展望)

### 特長
#### 1. 特長1
**時間ではなく「何をしているか」で休憩を決める。** 休憩アプリの多くは時間で通知します(25 分、30 分など)。ひといきは、AI に判断を求められた回数や、エラーを貼った回数でたまる速さが変わります。いちばん重い作業なら 25 分、ふつうなら 50 分で通知が出ます(目安の値。実際の作業での例は「使ってみた結果」に書きます)。

#### 2. 特長2
**作業の邪魔をしない。** 区切りまで待つ考え方は、既存の休憩アプリにもあります。ひといきは、AI が生成している間と、**長い回答を読み終えるまで**を見て待ちます。入力中や書きかけがある間も声をかけません。断れる 3 つのボタン(「今 ○ 分休む」「次の区切りで」「今回は不要」)があり、「今回は不要」を押すたびに次までの間隔が延びます(15 → 30 → 60 分)。作業の途中で割り込むと苛立ちや再開のコストが増える、という通知の研究(Iqbal & Bailey ほか)の考え方を、休憩に当てはめました。

#### 3. 特長3
**なぜ休もうと言われたかが分かる。** 計算は足し算なので、どの要素がどれだけ器をためたかを、そのまま理由として見せられます。カメラは使いません。会話の本文は拡張に保存しません(記録は件数・文字数・時刻・操作だけ)。判断・確認の分類をオンにすると、1 往復ごとに本文を Anthropic の API に送ります(キーは自分で入れます)。

### 今後の展望
- **開発の現場に広げる**: Claude Code・Codex の hooks からは、承認待ちやテストの失敗まで取れます。計算の部分は画面と切り離してあるので、出来事の形を合わせれば同じ計算につなげられます。VS Code の拡張も同じです
- **本人に合わせる**: 「役立った?」の答えや「あとで」を押した回数から、たまる速さを本人に合わせます
- **配れる形にする**: 今は自分たちで使う試作で、API キーはブラウザの中にあります。配るときは、サーバーを通す形に変えます

### 注力したこと（こだわり等）
* **根拠のある所と、仮置きの所を分けた**: 2 層の器(すぐ回復する負担と、その日は残る負担)は疲労の研究(Müller et al., Nature Communications 2021。体の努力の実験で、頭の作業で確かめられたものではない)の形を参考にしました。読む速さは日本語 653 字/分(小林・川嶋 2018)、英語 238 語/分(Brysbaert 2019)です。休憩の長さは、厚生労働省「情報機器作業における労働衛生管理のためのガイドライン」の「連続作業は 1 時間以内、10〜15 分の作業休止」に合わせました。要素ごとの重みには研究の根拠がないので、等重みの仮置きにして、そうはっきり書いています
* **LLM に点数を出させない**: LLM には「判断を求めた箇所」「動かないという報告」「別の話題に移ったか」という**出来事**だけを抜き出させます。負担の計算は、拡張の中の決まった式で行います
* **先行研究との位置づけ**: 作業ログから休憩の好機を予測する研究はあります(Kaur et al., CHI 2020)。ひといきは、AI との開発で増えた確認・判断の手がかりを、カメラなしで使います
* 表示は「ログから推定した作業の負担の目安」です。疲労を測っているわけではありません
