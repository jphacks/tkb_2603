# ひといき(仮名)

ChatGPT Web での作業の**中身**(読む量・判断・確認・検証・切替・作業時間)から「脳にかかる負担」の目安を計算します。器がたまったら、作業の**区切り**で休憩を提案する Chrome 拡張です。JPHACKS 2026 東京B 向けの試作です。

> 表示している値は、ログから推定した作業の負担の目安です。疲労を測っているわけではありません。係数は仮置きです。

## 動かし方
1. `npm install`
2. `npm run build`。`.output/chrome-mv3/` ができます
3. Chrome で `chrome://extensions` を開き、「デベロッパーモード」をオンにして「パッケージ化されていない拡張機能を読み込む」から `.output/chrome-mv3/` を選びます
4. 拡張の「詳細」→「拡張機能のオプション」を開き、Anthropic の API キーを入れて「キーを保存」を押します。キーが無くても動きますが、判断は「未計測」になります
5. https://chatgpt.com を開くと、右下に「計測中 ○%」が出ます。押すと右側に作業モニターが開きます。「診断」で、画面の取り方がうまくいっているか確かめられます。「休憩する」で休憩画面も試せます

開発中は `npm run dev` で、HMR つきの Chrome が立ち上がります。テストは `npm test` です。

UI の参照画像は `docs/design/` にあります。ChatGPT のライト／ダーク設定に追従し、右側パネルに全体の器と5項目のバー・割合を表示します。5項目は前回の休憩から負担をためた要因の内訳です。直近30分のグラフは「推移を見る」に折りたたんであります。

UI変更の理由・互換性・レビュー手順は [UI_DESIGN_DECISIONS.md](UI_DESIGN_DECISIONS.md) にまとめています。

全体の器・休憩ボタン・「計測中」ボタンは、90%未満が通常色、90%以上が黄色、100%以上が赤になります。100%を超えても蓄積を続け、数値は120%など実際の値を表示します。バーとリングは100%で満杯にし、詳細では赤いバーと「100%を超えています！ 現在120%」で示します。推移グラフの縦軸は超過分に合わせて広がります。通知の2択は「今○分休む」「区切りがついたら休む」です。後者は再通知や自動開始をせず、右下に「区切りがついたら／○分休む」の2段表示の休憩ボタンを残します。待機中も計測を続け、押した時点の器に応じて休憩時間を決めます。開始待ちは保存され、タブ間で共有されます。3時間の区切りでは解除されます。従来の自動タイマー設定も、ほかの設定を保って通知方式として読み込みます。

休憩の通知は画面右上（上から80px、狭い画面では72px）に表示します。右下の2つのボタンは入力欄全体の16px上に配置し、入力欄の伸縮・画面サイズ変更・会話の切替に追従します。入力欄を検出できない場合は下端から144pxに置きます。休憩ボタンは幅176px・高さ56pxを基本とし、小さく「区切りがついたら」、大きく「○分休む」と表示します。分数は現在の器と休憩時間の設定に連動します。休憩ボタンの背景は90%以上で明るい黄色、100%以上で赤に切り替えます。計測中ボタンは通常の背景を保ち、数値・リング・枠線の色を同じタイミングで切り替えて、休憩の操作と計測状態を見分けやすくします。表示が80%未満なら「−」で計測中表示を40px四方の葉のアイコンに折りたためます。アイコンを押すと数値表示に戻り、通常表示から詳細を開けます。80%以上では数値表示に自動で戻し、折りたたみ操作を出しません。折りたたみの選択はこのページを開いている間保ち、80%未満に戻ると再び適用します。

休憩タイマーは計算時計に連動した分・秒表示です。休憩開始ごとに背伸び・肩回し・左右にゆらすの1種類をランダムに選んで保存し、その休憩中は同じ運動と案内文を表示します。

## 仕組み(計画 v2.2)
```
1 分ごとの中身 e = (読む量 + 判断 + 確認・検証 + 切替 + 作業時間) ÷ 5   … 各 0〜1、等重み
作業中:          RF += 0.98 × 3.2 × e     UF += 0.02 × 3.2 × e
休憩タイマー中:  RF −= 8 / 分             (休憩タイマーの間だけ減る)
器 = RF + UF(100を超えても蓄積)→ 80 で「休憩が必要」→ 作業の区切りで声をかける
```
| 要素 | 取り方 |
|---|---|
| 読む量 | 回答の文字数 ÷ 653 字/分(英語は 238 語/分)を「読む残り時間」として持ち、その間は 1 |
| 判断 | LLM が回答から「選択・承認・決定を求めた箇所」を抜き出す。直近 5 分の件数 ÷ 2 で頭打ち |
| 確認・検証 | エラー文らしい貼り付け(手元の正規表現)+ LLM が「動かない」「合ってる?」などを抜き出す |
| 切替 | 会話の切替(URL)+ LLM が「独立した新しい目標」を判定 |
| 作業時間 | ChatGPT のタブが表に出ていて、直近 5 分に操作があれば 1 |

- 区切りの条件: 生成中ではない・入力中ではない・入力欄が空・読む残り時間が 1 分未満・回答から 10 秒たった・タブが表に出ている
- ボタン: 「今○分休む」「区切りがついたら休む」。区切りを待つ場合は右下の「○分休む」を押すまで計測を続け、休憩は自動で始めない
- 休憩の長さ: 器が 80 なら 10 分、100 以上なら最大 15 分。超過分も同じ回復速度で減るため、大きく超過した場合は休憩後に値が残ることがある
- 3 時間 ChatGPT を使わなかったら、1 日の区切りとして器を 0 に戻します
- 参考にしたもの: 2 層の形は Müller et al. 2021(Nature Communications)、読む速さは小林・川嶋 2018 と Brysbaert 2019、休憩の目安は厚生労働省「情報機器作業における労働衛生管理のためのガイドライン」です。区切りで声をかける考え方は Iqbal & Bailey などです

## プライバシー
- 会話の本文は、拡張に保存しません。記録するのは件数・文字数・時刻・操作だけです(設定画面から JSON で書き出せます)
- LLM の分類を有効にすると、1 往復ごとに本文を Anthropic の API に送ります
- API キーはブラウザの `chrome.storage.local` に平文で置きます。自分たちだけで使う前提です。配るときはサーバー経由に変えます
- OpenAI の利用規約には「出力を自動で抜き出すことの禁止」があります。自分たちで使う範囲を超えて配る場合は、考え直す必要があります

## 構成
```
src/core/       計算(純粋な関数+テスト)。types / model / gate / detect
src/content/    ChatGPT の画面から取る(chatgpt.ts)と、器を動かす係(runner.ts)
src/shared/     設定・保存・記録、LLM の分類(classifier.ts)、メッセージの型
src/ui/         画面(App.tsx)、声かけ(copy.ts)、ピクトグラム、CSS
entrypoints/    background(API 呼び出し)、chatgpt.content(画面に UI を重ねる)、options(設定)
```
