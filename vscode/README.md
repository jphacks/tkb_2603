# ひといき(VS Code 試作)

Chrome 拡張と同じ計算(`../src/core/`)を、VS Code での作業の出来事で動かす試作です。器がたまり、区切りで「ひと休みしませんか」と提案するところまでを作っています。

## 取るもの

| 要素 | VS Code から取るもの |
|---|---|
| 読む量 | 入力ではない、まとまった挿入(1 回 100 字以上。読む量に入れるのは 1 回 500 字まで)。補完の受け入れと人の貼り付けは区別できません |
| 確認・検証 | **タスクと、シェル統合が効いたターミナル**のコマンドの終了コードが 0 以外のもの。Test Explorer で回したテストは取れません |
| 切替 | アクティブなファイルの切替(5 秒以内の行き来は数えません) |
| 作業時間 | 入力・切替・コマンドが直近 5 分にあったか |
| 判断 | 取れません(未計測)。そのぶん器は遅めにたまります |

## 試作の範囲

- **VS Code 版は提案まで**です。休憩のタイマー・メモ・おかえりは Chrome 版にあります。休憩が無いので、器は下がりません(3 時間作業が無いか、「ひといき: 器を 0 に戻す」で 0 に戻ります)。提案を出したら、次の提案まで 15 → 30 → 60 分空けます
- **ウィンドウごとに器が別**です。VS Code の窓を 2 つ開くと、それぞれが別に数えます(保存は最後に書いた方が残ります)。Chrome 版の器とも別です
- 提案を出すのは、入力が 3 秒止まり、終わる種類のタスクもデバッグも動いておらず、VS Code の窓が前にある時です。`tsc --watch` のような終わらないタスクは邪魔をしません

## 動かし方

1. `npm install`
2. VS Code でこの `vscode/` フォルダを開き、F5(「ひといき(拡張機能の開発ホスト)」)
3. 開発ホストの設定で `hitoiki.speed` を 60〜120 にすると、1 秒で計算上 1〜2 分進みます
4. 失敗するコマンドやタスクを何回か動かすと、右下の「ひといき n%」が上がり、しきい値(`hitoiki.threshold`、既定 80)を超えると、区切りで提案が出ます

## 確かめ

- `npm test`: 出来事 → 計算の変換(VS Code の API をまねた形)
- `npm run e2e`: インストール済みの VS Code を使い捨てのプロファイルで開き、倍速で失敗するタスクを繰り返して、提案が出るまでを確かめます。VS Code の窓が 1 分ほど画面に出るので、その間は触らないでください
